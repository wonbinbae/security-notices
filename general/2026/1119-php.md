# [보안공지] PHP 제품 보안 업데이트 공지

게시일 2026-11-19

## 개요

■ The PHP Group은 자사 제품에서 발생하는 취약점을 해결한 보안 업데이트 발표 [1][2][3][4]  
■ 영향받는 버전을 사용 중인 사용자는 해결 방안에 따라 최신 버전으로 업데이트 권고

## 설명

■ PHP에서 발생하는 Improper Input Validation, Deserialization of Untrusted Data 취약점(CVE-2026-115560) [1][5]  
■ PHP에서 발생하는 Time-of-check Time-of-use (TOCTOU) Race Condition, Improper Synchronization 취약점(CVE-2026-126714) [1][6]  
■ PHP에서 발생하는 Use After Free, Incomplete Cleanup 취약점(CVE-2026-129182) [1][7]  
■ PHP에서 발생하는 HTTP Request Smuggling, Always-Incorrect Control Flow Implementation 취약점(CVE-2026-129289) [1][8]  
■ PHP에서 발생하는 Use After Free 취약점(CVE-2026-129474) [1][9]  
■ PHP에서 발생하는 Use After Free, Incomplete Cleanup 취약점(CVE-2026-129481) [1][10]  
■ PHP에서 발생하는 Use After Free, Incomplete Cleanup 취약점(CVE-2026-129496) [1][11]  

※ CVE-2026-126714(phpAfterShell)는 기본 설정(파일 세션 + 업로드 진행)에서 multipart 요청만으로 세션 파일 조작이 가능하나, 세션 파일 쓰기 도중 프로세스가 중단되는 타이밍과 이후 session_start() 호출(앱마다 다름)이 추가로 필요 [6][12]  
※ CVE-2026-129289는 웹서버가 PHP-FPM, LSAPI 백엔드 연결을 재사용하도록 설정된 경우(nginx `fastcgi_keep_conn on`, Apache `mod_proxy_fcgi` `enablereuse=on` 등)에 해당 [8]  
※ CVE-2026-115560은 세션 업로드 진행률 기능이 활성화되어 있고 세션을 쓰는 쪽과 읽는 쪽의 `session.serialize_handler`가 다른 경우에 해당 [5]  
※ CVE-2026-129474, CVE-2026-129182는 PHP 8.5에만 해당 [7][9]

## 영향시스템

Server, Web/WAS, Application

※ 즉시 업데이트가 어려운 경우 아래 임시 조치 적용 후 PHP 프로세스 재시작 권고 [5][6][7][8][9]  
　- CVE-2026-126714, CVE-2026-115560 : 업로드 진행률 기능을 사용하지 않으면 `session.upload_progress.enabled=0` 설정 (단, 세션에 외부 입력을 대량 저장하는 애플리케이션은 CVE-2026-126714 위험이 남으므로 업데이트 필요)  
　- CVE-2026-129289 : 웹서버의 PHP-FPM, LSAPI 백엔드 연결 재사용 비활성화  
　- CVE-2026-129474, CVE-2026-129182 : `fatal_error_backtraces=0` 설정 (CVE-2026-129474는 `zend.exception_ignore_args=1`로도 완화 가능)  
※ CVE-2026-115560 패치 버전부터 세션 업로드 진행률 기능이 기본 비활성화되나, 설정에서 명시적으로 활성화한 경우 그대로 유지되므로 설정 확인 필요 [5]  
※ 리눅스 배포판 등에서 제공하는 PHP 패키지는 버전 번호 변경 없이 패치가 반영될 수 있으므로 해당 배포판의 보안 공지 기준으로 판단 [12]  
※ PHP 8.1 이하 지원 종료(EOL) 버전은 패치 미제공, 지원 버전으로 업그레이드 후 패치 적용 권고 [1]  
※ 하단의 참고사이트를 확인하여 업데이트 수행 [1][2][3][4]
